# Эмулятор плат для тестирования

Документ описывает встроенные эмуляторы устройств, позволяющие тестировать
приложение **без подключённого оборудования** и без виртуальных COM-портов.

Эмулируются две платы:

| Плата | Протокол | Эмулятор | Где живёт |
|-------|----------|----------|-----------|
| Интеррогатор | потоковый JSON | `MockSerialPort` | `features/serial/services/mock-port.service.ts` |
| ASE-источник (Connet VASS) | бинарный запрос/ответ `AA 55` | `AseDevice` + `MockAsePort` | `features/ase/` |

Оба эмулятора включаются **одним флагом** — переменной окружения
`WITH_MOCK_PORTS`.

---

## Как включить

В файле `.env` в корне проекта:

```dotenv
WITH_MOCK_PORTS=true
```

Флаг читается в [`src/electron/core/env.ts`](../../core/env.ts) и попадает в
`ENV.WITH_MOCK_PORTS`. После перезапуска приложения:

- список портов (`serial.getPorts()`) возвращает mock-порты
  (`/dev/ttyUSB0`, `/dev/ttyUSB1`, `/dev/ttyUSB2`);
- подключение к интеррогатору стартует поток сгенерированных JSON-данных;
- подключение ASE-источника идёт через in-process эмулятор устройства.

> При `WITH_MOCK_PORTS=false` (или отсутствии переменной) используются
> реальные порты — поведение приложения не меняется.

---

## 1. Эмулятор интеррогатора

Уже существовал в проекте. `MockSerialPort` раз в
`TIMEOUTS.MOCK_DATA_INTERVAL` (1 c) отправляет JSON-строку с полями
`P0..P15` (мощность) и `stdDev0..15`. Значения зависят от индекса порта и
слегка шумят, имитируя живой сигнал. Данные проходят весь обычный путь:
`data-processor` → БД → IPC → графики/дашборд.

Дополнительная настройка не требуется — достаточно флага и подключения к
mock-порту на странице настроек.

---

## 2. Эмулятор ASE-источника

Состоит из двух слоёв:

### `AseDevice` — логика «прошивки» платы

Чистый класс без I/O ([`ase.device.ts`](./ase.device.ts)). Принимает кадр
запроса `ПК → ASE` и возвращает кадр ответа `ASE → ПК` строго по протоколу.

Внутреннее состояние: `enabled` (излучение вкл/выкл) и `rawPower` (текущее
сырое значение мощности).

Поддерживаемые команды:

| CMD | Назначение | Ответ эмулятора |
|-----|-----------|-----------------|
| `0xD1` | Параметры устройства | DATA длиной 24 байта: `unit` (offset 17), `max_setting` (18/19, LE), `coeff` (23) |
| `0xC1` | Вкл/выкл излучения (`01`/`00`) | эхо состояния |
| `0xC3` | Установка мощности (`raw_u16` LE) | эхо записанного `raw` (с ограничением `raw_max = max_setting * coeff`) |
| прочее | — | эхо CMD без данных |

Параметры устройства по умолчанию (`ASE_MOCK_DEVICE` в
[`ase.constants.ts`](./ase.constants.ts)):

```
unit        = 0
max_setting = 20      // макс. мощность в единицах устройства
coeff       = 100     // raw = round(mW * coeff), raw_max = 20 * 100 = 2000
```

Эти значения соответствуют примеру из ТЗ (`coeff = 100`, `20 mW → raw 2000`).
Их можно переопределить, передав `Partial<AseDeviceConfig>` в конструктор
`AseDevice`/`MockAsePort`.

### `MockAsePort` — in-process порт

Реализует интерфейс `IAsePort` (тот же, что и реальный `AsePort`):
`open()`, `sendCommand(frame)`, `close()`, `isOpen`, `path`. Вместо
физического порта прогоняет кадры через `AseDevice` и возвращает ответ с
небольшой задержкой (`responseDelay`), имитируя устройство.

### Точка переключения

Фабрика [`ase.port.factory.ts`](./ase.port.factory.ts) выбирает транспорт:

```ts
createAsePort(path, onClosed, onError): IAsePort {
  if (ENV.WITH_MOCK_PORTS) return new MockAsePort(path, onClosed, onError);
  return new AsePort(path, onClosed, onError);
}
```

`AseService` использует только `createAsePort`, поэтому весь UI (виджет
«Управление ASE-источником») работает с эмулятором прозрачно.

## Пример обмена (ASE)

Запрос параметров и ответ эмулятора:

```
ПК  → ASE:  AA 55 D1 00 00 00
ASE → ПК:   55 AA D1 18 <24 байта DATA> <CRC_L> <CRC_H>
            // DATA[17]=00 unit, DATA[18]=14 DATA[19]=00 → max_setting=20,
            // DATA[23]=64 → coeff=100
```

Установка мощности 10 mW (`raw = 10 * 100 = 1000 = 0x03E8`):

```
ПК  → ASE:  AA 55 C3 02 E8 03 EB 00      // CRC = E8 + 03 = 0x03EB
ASE → ПК:   55 AA C3 02 E8 03 EB 00      // эхо записанного raw
```

Включение излучения:

```
ПК  → ASE:  AA 55 C1 01 01 01 00
ASE → ПК:   55 AA C1 01 01 01 00
```

## Как расширять

- **Другие параметры устройства**: передайте конфиг в `MockAsePort`
  (потребуется небольшая правка фабрики, если нужно из env).
- **Эмуляция ошибок/таймаутов**: добавьте ветки в `AseDevice.handleFrame`
  (например, не отвечать на команду) или увеличьте `responseDelay` выше
  `ASE_RESPONSE_TIMEOUT`, чтобы протестировать обработку таймаута в `AsePort`.
- **Unit-тесты протокола**: `AseDevice` и функции `ase.protocol.ts`
  (`buildFrame`, `buildResponseFrame`, `parseRequest`, `parseResponse`,
  `parseInfo`, `mwToRaw`) не требуют I/O и тестируются напрямую.
